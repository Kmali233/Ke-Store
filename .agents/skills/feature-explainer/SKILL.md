# 功能完成后的 HTML 图文讲解

本技能是功能交付的收尾步骤。先完成用户要求的功能和适当验证，再制作讲解；确认功能完成且用户本次未要求跳过时执行。所有命令从仓库根目录运行。

## 生成与交付

1. **登记。** 使用 UserPromptSubmit 钩子提供的 session_id；钩子尚未信任时可用环境中的 CODEX_THREAD_ID。执行 `python scripts/feature-explainer.py require --name "功能名称" --stage "06-管理操作审计模块" --session-id "会话ID"`，stage 换成当前功能对应的真实阶段目录名。省略时仅在阶段名能唯一匹配功能名时自动选择，无法匹配时先查看现有阶段计划确定。返回值的 html 是图文输出路径，implementation_document 是相对于仓库父目录的说明路径；幂等重试同名登记不会重置基线。
2. **收集事实。** 读取当前实现、该功能的实际修改范围和相关验证结果。围绕一条完整业务操作整理入口、身份、主要方法、事务/状态、数据结果。区分原有实现、本轮修改、预留能力；只描述真正遇到的问题。
3. **撰写说明并生成页面。** 先把本轮实现内容、修改文件、实际验证结果与边界写入返回的 `implementation_document` 路径，文件名为《详细实现说明.md》。已有说明先保留可恢复副本再更新。位置必须在仓库同级的 `基础模块后阶段计划/<登记的阶段目录>/`，不要在模块目录另留一份。然后制作 HTML： 参考 [assets/reference.html](assets/reference.html) 的配色、留白、图文并置、分步交互和手机布局，生成返回路径中的单文件 HTML。它是管理审计的视觉参考；所有业务内容、源码链接、示意图、步骤数量和验证结论都要按新功能重写。用户提供新的参考 HTML 时，以用户的参考为准。
4. **检查。** 校验源码/证据链接、锚点和 JavaScript；在可用浏览器中查看桌面与手机布局，点击实际交互。检查受阻时修复可修复部分，并在交付中准确说明尚未检查的部分。运行 `python scripts/feature-explainer.py complete --session-id "会话ID"`；它检查 HTML 是本次更新、包含功能名与内联图、主要章节及有效源码链接，并检查对应阶段的《详细实现说明.md》存在、非空且位置与登记一致。说明缺失、空白或放错位置都会要求补齐。
5. **交付。** 最终回复提供实现说明与 HTML 的绝对路径链接，简述覆盖内容和检查结果。有可用截图时可附一张预览；不再展开大段文字重复页面。

## 页面内容

- 先用一句话说明功能做什么，再用具体例子串起一条业务操作。术语与实际类/方法对应，调用链要走到最终数据结果。
- 图随内容：调用链图配合分步讲解；涉及事务、状态流转、并发或失败路径时，用相应的交互示意呈现。标明“教学示意”，真实截图与运行证据单独注明来源。
- 默认讲“怎么实现”。确实遇到问题时才添加“问题 → 处理 → 验证”，没有问题就省略；除非用户明确要求，不扩展设计原因、面试表达或自测问答。
- 验证只概括证明了什么；具体日期、命令和证据可折叠。未执行、跳过、历史记录与本轮通过要清晰区分。
- 展示该功能涉及的实际修改文件与源码阅读索引；保留用户原有未提交改动的贡献边界。未实现能力写为预留或后续阶段。

## 产物与边界

- 输出为 `output/功能实现讲解/<功能名称>.html`；HTML、CSS、JavaScript、SVG/图片均内嵌，无远程字体、CDN或生产依赖。适配手机，支持键盘操作和打印；打印至少保留完整静态主调用链。
- 页面 title 包含登记的功能名称，至少一幅内联 SVG 图，图有可理解的文字说明。按实际内容组织章节，不固定为审计示例的六步。
- 源码索引默认点击后在已启动的 IDEA 中打开并定位到实际方法行：先核对行号，再运行 `python scripts/idea_links.py url --file "仓库相对路径" --line 42` 生成 `xiaoke-idea://open?file=...&line=...` 链接；HTML 中正确转义 `&`。旁边保留相对路径的“浏览器查看”链接，注明第一次浏览器可能询问是否打开外部应用。校验器会检查 IDEA 链接的文件和行号。
- 本机的 IDEA 打开入口由 `scripts/idea_links.py` 管理，使用当前用户的项目专用 URL 协议；换机器时需先确认 IDEA 安装路径，再运行 `python scripts/idea_links.py install --idea "IDEA 的 idea64.exe 绝对路径"`。无需修改 .java 默认打开方式。单独分享 HTML 后，本地源码入口依赖接收方的项目与此配置。内容避开密码、令牌、真实收货信息及原始敏感日志。
- 同名报告在保留原文可恢复副本后更新，其他功能的 HTML 保留。`output/` 保持 Git 忽略；技能与钩子配置可版本管理。不要运行 Git 提交钩子、后台循环或嵌套 Codex 进程生成报告。
- 实现说明统一存放在 `../基础模块后阶段计划/<对应阶段目录>/详细实现说明.md`，HTML 使用正确的相对路径链接到它。阶段目录必须真实存在，无法唯一匹配时使用 require 的 --stage 明确指定。
- Stop 钩子同时检查已登记的实现说明和 HTML，最多请求一次补齐。确实无法交付、用户取消或明确跳过时，执行 `python scripts/feature-explainer.py defer --session-id "会话ID" --reason "实际情况"`，并如实报告；不要把生成失败写成功。该命令不代替完成能够继续完成的工作。
