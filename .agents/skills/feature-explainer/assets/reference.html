先看这一件事

这个模块记录“谁在什么时候，对哪个对象做了什么”。商品、SKU、分类、发货、账号与权限变更共用 xiaoke-audit；它是普通 JAR，随各业务服务运行。

教学记录；ID 为示例，价格来自已验收的改价场景。图中未展示全部数据库字段。
1
身份取自已验证的管理员上下文

AuditWriter 从 AdminContext 取管理员 ID；可信的进程内部调用没有管理员身份时，明确记录 SYSTEM。

2
只写白名单差异

AuditChanges 接收价格、状态、角色 ID 等受控字段。商品名称、描述等自由文本只记录“是否变化”。

3
归一化后再比较

价格 1、1.0、1.00 视为相同；角色 ID 排序后比较。无实质差异，不插入事件。

4
敏感原文不进入载荷

不序列化整个请求 DTO，也不把请求体写入安全日志。

密码 / 哈希JWT支付密钥收货地址运单原文
04

从操作记录，回到一次请求

查询入口位于管理员服务；按操作者、订单号或 traceId 定位。

后台 JWT→audit:read→AuditReader.page→摘要校验 + 分页结果
GET/api/admin/audit/page?targetType=PRODUCT&targetId=100
01 / 有界检索

按操作者、对象、动作、traceId、时间过滤。默认最近 30 天，单次最多 31 天；每页最多 100 条。

02 / 权限控制

接口要求 audit:read；V6 迁移只把这项权限授予系统管理员角色。没有修改或删除审计的接口。

03 / 检测摘要异常

重新计算摘要；不匹配时返回 integrityValid=false、changes=null。该校验不等于不可篡改存储。

查发货记录时使用 targetType=ORDER、targetId=订单号；按请求查时传响应头中的 traceId。
